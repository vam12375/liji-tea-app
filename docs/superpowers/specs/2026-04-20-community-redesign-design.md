# 社区改版设计稿

日期：2026-04-20

## 1. 目标

本设计稿用于为李记茶 App 的社区模块做一次面向增长、转化和内容沉淀的结构性改版。

当前社区已经具备发帖、故事、点赞、收藏、评论、我的帖子、积分激励和互动通知这些基础能力，但整体仍停留在“内容列表 + 基础互动”阶段。它能展示内容，却还没有形成主流社区产品常见的五层能力：

- 分发层：把对的人和内容匹配起来
- 搜索层：把内容变成可复用知识
- 关系层：让用户形成稳定回访路径
- 治理层：让社区质量可控
- 转化层：把内容消费自然导向商品决策

本期设计遵循以下原则：

- KISS：不做重视频、直播、附近、复杂社交关系，先把内容分发和交易闭环打通
- YAGNI：不把李记茶做成泛社区平台，只服务“看茶、学茶、买茶、问茶”
- SOLID：社区继续拆成内容对象、分发规则、互动机制、搜索沉淀、转化挂品五个清晰边界

## 2. 当前现状

### 2.1 已有能力

- 社区首页已把推荐、茶友、茶道、问答合在一个入口中
- 帖子支持三类内容：晒图动态、冲泡记录、发起提问
- 已有故事流、帖子详情、我的帖子
- 已有点赞、收藏、评论、评论点赞
- 已有“首次发帖积分”激励
- 已有社区互动通知与 push 队列触发器

### 2.2 当前问题

1. 社区首页的组织方式偏“来源导向”，不是“任务导向”

- 现在的“推荐 / 茶友 / 茶道 / 问答”更像内容来源划分
- 用户真实需求往往是“今天看点什么”“这个茶怎么泡”“这个问题谁能回答”“有没有同款可以买”

2. 分发机制过于原始

- 当前帖子主列表按 `created_at desc` 拉取
- “热议”只是当前帖子列表内按点赞数取前 3
- 这还不是主流社区意义上的推荐流

3. 内容还没有沉淀成知识库

- 搜索仍是商品搜索，不是社区搜索
- 问答没有“最佳回答”“相似问题”“问题去重”
- 冲泡记录没有“参数复用”“关联茶品”

4. 商业闭环太弱

- 用户看到优质内容后，缺少自然的“查看同款茶 / 加入购物车 / 保存冲泡参数”动作
- 社区和商城仍是相邻模块，不是同一决策链

5. 治理能力不完整

- 前台有轻量举报反馈，但没有真正的社区审核台
- 数据库已支持评论回复，但前台仍只展示扁平评论

## 4. 方案比较

### 方案 A：继续维持“内容混合页”，只补交互细节

优点：

- 改动最小
- 上线最快

缺点：

- 只能修补体验问题，不能改变社区结构性弱点
- 分发、搜索、转化、治理问题都会继续累积
- 后续功能越堆越乱

结论：

- 不推荐

### 方案 B：做“小红书式发现流 + 知乎式问答沉淀 + 电商挂品”

优点：

- 贴合茶行业“内容影响决策”的真实链路
- 既能保留 UGC 温度，也能沉淀知识与购买理由
- 改造成本可控，能复用当前帖子、评论、通知、积分底座

缺点：

- 需要重做社区首页的信息架构
- 需要为帖子补标签、关联商品、问题状态等字段

结论：

- 推荐方案

### 方案 C：向 TikTok 靠拢，做短视频优先社区

优点：

- 理论上分发效率高
- 更容易放大情绪价值

缺点：

- 创作成本高
- 内容生产、审核、推荐、播放器、性能开销都显著上升
- 与当前图文 + 冲泡 + 问答底座不匹配

结论：

- 当前阶段不推荐

## 5. 推荐定位

推荐把李记茶社区定义为：

**“帮助用户更快完成选茶、学茶、买茶决策的内容社区。”**

这意味着社区的核心目标不是“社交关系活跃”，而是：

- 让用户看到值得喝的茶
- 让用户学会怎么泡
- 让用户快速提出问题并得到可用答案
- 让用户在看到内容后顺手完成购买或收藏

因此，社区不是商城旁边的“娱乐区”，而是商城前面的“决策区”。

## 6. 信息架构

### 6.1 社区首页一级结构

推荐把当前 `推荐 / 茶友 / 茶道 / 问答` 改为：

- 推荐
- 问答
- 冲泡

说明：

- “推荐”负责混合分发，是主入口
- “问答”负责问题沉淀和经验复用
- “冲泡”负责结构化茶饮经验和参数沉淀

不建议保留“茶友”作为一级标签：

- “茶友”只是内容来源，不是用户任务
- 它会和“推荐”形成边界重叠

不建议保留“茶道”作为一级标签：

- 官方内容更适合作为推荐流里的内容卡，而不是独立频道
- 当前 `culture` 已经重定向到社区，也说明内容与社区应该合流

### 6.2 二级入口

在社区页顶部增加以下轻入口：

- 搜索
- 收藏
- 我的帖子
- 话题/标签页入口

推荐页内保留故事流，但定位要改成：

- 今日茶席
- 新到茶样
- 店员试喝
- 茶友速览

不要把故事流当主叙事，只把它作为“轻量回访入口”。

## 7. 内容模型

### 7.1 保留三类主内容

1. 晒图动态

- 适合种草、茶席、日常喝茶、茶器展示
- 目标是氛围感和购买兴趣

2. 冲泡记录

- 适合结构化经验沉淀
- 目标是参数复用和专业可信度

3. 提问帖

- 适合解决具体问题
- 目标是社区答疑和知识沉淀

### 7.2 每类内容补充的关键字段

所有内容统一补充：

- `tea_category`：茶类
- `scene_tags`：场景标签，如早茶、办公、送礼、入门
- `product_ids`：关联商品
- `topic_tags`：内容标签

冲泡记录额外补充：

- `equipment`
- `brew_rounds`
- `taste_notes`
- `recommended_for`

提问帖额外补充：

- `question_status`：待回答 / 已解决
- `best_comment_id`
- `related_article_ids`
- `related_product_ids`

### 7.3 卡片策略

推荐流中至少保留四种卡片：

- 种草卡：图文 + 商品挂卡
- 冲泡卡：参数块 + 心得 + 商品挂卡
- 问答卡：标题 + 摘要 + 回答数 + 最佳回答标记
- 官方卡：文章摘要 / 茶知识 / 节气专题

## 8. 分发机制

### 8.1 推荐流不是纯时间流

推荐流建议改成“轻量混合推荐”，而不是单纯按时间排序。

V1 可解释排序信号建议：

- 新鲜度
- 收藏数
- 评论数
- 点赞数
- 内容完整度
- 是否挂商品
- 是否命中用户近 30 天浏览/收藏/购买的茶类
- 是否命中用户最近搜索词

### 8.2 推荐流配比

推荐页建议采用固定配比，而不是完全自由竞争：

- 45% 晒图动态 / 种草卡
- 25% 冲泡记录
- 20% 问答
- 10% 官方内容

原因：

- 茶社区需要氛围，也需要实用性
- 问答和官方内容过多会变成工具区
- 晒图和冲泡过多又会丢失知识沉淀

### 8.3 关注关系的处理

本期不建议上线完整“关注/粉丝”体系。

原因：

- 当前冷启动阶段，关系链不是主要增长源
- 做了关注也没有足够创作者供用户关注

推荐替代方案：

- 先做“收藏作者内容”
- 先做“相似内容继续看”
- 先做“同类茶继续看”

等内容量和活跃度达到一定规模后，再补“关注”。

## 9. 搜索与沉淀

### 9.1 搜索要从商品搜索升级为“全站搜索”

搜索结果至少分四类：

- 商品
- 帖子
- 问答
- 茶知识 / 官方内容

### 9.2 搜索建议优先支持的条件

- 茶名
- 茶类
- 场景词
- 冲泡问题
- 器具名
- 功效感知词

### 9.3 沉淀目标

用户不只是“刷一遍就走”，而是能：

- 搜到“龙井怎么泡”
- 找到“送长辈喝什么茶”
- 看到“新手紫砂壶怎么选”
- 保存一条冲泡参数，下次继续用

这一步决定社区是不是知识资产，而不是只做瞬时内容。

## 10. 转化闭环

### 10.1 核心原则

社区商业化不能硬插广告位，应该沿着内容意图自然转化。

### 10.2 推荐挂载动作

在卡片和详情页增加这些动作：

- 查看同款茶
- 查看相关茶具
- 保存冲泡参数
- 加入购物车
- 收藏商品

### 10.3 关键联动

1. 社区内容页 -> 商品详情

- 帖子挂商品卡
- 问答页挂相关茶/器具

2. 商品详情 -> 社区内容

- 商品页展示“茶友怎么泡”“真实晒图”“相关问答”

3. 冲泡内容 -> 复购

- 保存参数后，下次在商品详情或冲泡记录页快速复用

### 10.4 不建议做的商业化

- 首页大横幅硬卖货
- 社区内高频弹窗促销
- 把推荐流做成商品流伪装内容流

这会直接破坏社区信任感。

## 11. 互动与治理

### 11.1 互动增强

优先补以下能力：

- 评论回复
- 问答“最佳回答”
- 收藏夹分组
- 内容标签点击跳转

当前数据库已经支持评论回复关系，但前台仍未展示，应优先补齐。

### 11.2 治理能力

必须补齐：

- 举报真实落库
- 社区 / 评论审核后台入口
- 重复问题处理
- 低质内容降权
- 违规内容下架

当前商家端 roadmap 已明确未来会有“社区 / 评论审核”，这部分应正式纳入社区设计范围，而不是继续停留在占位提示。

## 12. 激励机制

### 12.1 已有能力

- 首次发帖积分

### 12.2 推荐新增但不在首期强做

- 提问被设为“已解决”
- 回答被设为“最佳回答”
- 冲泡记录被收藏达到阈值
- 优质内容入选官方精选

原则：

- 奖励“可复用内容”，不是奖励刷屏
- 积分激励服务质量，不服务水内容

## 13. 实施分期

### Phase 1：结构重排

目标：

- 把社区从“混合列表”升级为“推荐 / 问答 / 冲泡”三主轴

范围：

- 重做社区首页信息架构
- 调整 tab
- 官方内容并入推荐流
- 保留故事流但弱化其主地位

### Phase 2：知识沉淀

目标：

- 让社区内容能被搜索、复用和解决问题

范围：

- 社区搜索
- 问答状态
- 最佳回答
- 评论回复
- 标签页

### Phase 3：交易闭环

目标：

- 让社区内容成为商品转化入口

范围：

- 挂商品卡
- 商品详情反向展示社区内容
- 保存冲泡参数
- 从内容直接加购

### Phase 4：治理与关系增强

目标：

- 提升社区质量与长期回访

范围：

- 社区审核入口
- 举报闭环
- 低质内容处理
- 关注关系评估

## 14. 对当前代码结构的影响

需要重点改造的区域：

- 社区首页入口与标签逻辑
  - `src/app/(tabs)/community.tsx`
- 帖子查询与 feed 组装
  - `src/stores/communityStore.posts.ts`
- 帖子内容模型与 mapper
  - `src/lib/communityModels.ts`
- 发帖页字段与内容类型扩展
  - `src/app/community/create.tsx`
- 帖子详情页的互动、评论、最佳回答、挂品区域
  - `src/app/post/[id].tsx`
- 搜索从商品搜索扩成全站搜索
  - `src/app/search.tsx`

## 15. 本期明确不做

- 完整关注/粉丝系统
- 附近的人 / 同城茶会
- 短视频优先
- 直播社区
- 私信系统
- 达人分销体系
- 复杂推荐平台化能力

这些都不是当前阶段的最高 ROI。

## 16. 结论

李记茶社区最适合走的不是“泛社交”路线，也不是“短视频优先”路线，而是：

**内容发现 + 问答沉淀 + 冲泡经验 + 商品闭环**。

这条路线的优势是：

- 和茶行业决策链天然一致
- 与现有代码底座兼容
- 改造后能直接提升内容价值、搜索价值和转化价值

本设计推荐后续先进入页面蓝图与状态设计阶段，再进入实现计划，不建议直接跳过设计去修改代码。
